背景与动机

随着 APT 攻击、勒索软件和僵尸网络不断演化，C2 通信已经从“明显异常外联”转向“伪装成正常业务流量”。攻击者可以隐藏域名、加密内容、降低通信频率，但仍然需要让受控主机与控制端保持联系，这使连接行为本身成为识别隐蔽威胁的关键入口。

在真实攻防场景中，C2 通信通常承担远程控制、任务下发、状态回传、横向移动协同和数据外传等功能。为了绕过边界设备和传统告警规则，攻击者往往将通信隐藏在 HTTPS、DNS、云服务 API 或周期性心跳连接之中，使单次请求看起来并不明显恶意。

这类通信未必产生大流量，也未必暴露明文 payload。即使通信内容完全加密，受害主机仍然会在连接时间、访问频率、数据大小、持续时间和外部目标稳定性上留下行为痕迹。C2Sherlock 的动机正是从这些“内容不可见但行为可度量”的元数据中发现异常规律，将海量流量转化为可排序、可解释、可溯源的安全线索。

隐蔽化

C2 流量伪装为普通业务访问，单次连接不一定触发传统告警。

周期化

受控主机持续向控制端发送 Beacon，用于状态同步与任务获取。

加密化

HTTPS、TLS 和 DNS 隧道削弱内容检测效果，元数据更重要。

低频化

攻击者可通过降低通信频率和加入抖动逃避简单周期检测。

现有方法的局限

隐蔽 C2 检测的难点不在于“是否存在外联”，而在于如何从大量正常外联中识别真正具有控制通道特征的异常行为。传统方案往往依赖单一视角，难以同时兼顾覆盖面、复杂模式识别和结果可解释性。

签名与情报依赖已知威胁

黑名单、域名、URL 或 payload 签名对已知样本有效，但攻击者更换基础设施、使用新注册域名或将 C2 托管在常见云平台后，命中率会显著下降。

单一统计规则容易被规避

固定阈值和简单周期规则能发现明显 Beacon，但面对随机抖动、长休眠、低频心跳和模拟人工浏览节奏的 C2 通信时，容易出现漏报。

纯深度模型缺少可解释链路

模型能够学习复杂模式，但若只输出概率分数，分析师难以判断“为什么可疑”，也难以将模型结论转化为溯源方向和处置动作。

我们需要的能力

  • 在无明文 payload 的情况下利用连接行为检测。
  • 同时识别明显周期 Beacon 和弱规则异常通信。
  • 输出可读证据链，而不是只给出一个黑盒分数。

C2Sherlock 的应对思路

  • 规则引擎负责快速筛查可疑连接。
  • LSTM 模型负责捕捉复杂时序模式。
  • AI 研判模块负责融合结果并生成可解释报告。

总体结构

C2Sherlock 的分析流程从 PCAP 文件上传开始。系统首先将原始数据包解析为结构化网络日志，再按通信关系构建连接行为特征；随后通过规则引擎完成统计评分，利用 LSTM 模型进行时序异常识别，最后融合多源检测结果，生成自然语言研判报告。

结果反馈与模型 / 规则持续优化

规则引擎

规则引擎承担第一层快速筛查任务。系统不直接依赖通信内容，而是以“内部主机—外部目标”为分析对象，聚合同一通信关系中的连接时间、数据量、持续时间和频率分布，判断其是否呈现 Beacon 式的自动化通信特征。

时间间隔规律性

连接间隔越稳定，越像固定心跳通信。这里用变异系数衡量离散程度。

CVinterval = σinterval / μinterval
Stime = 1 − min(CVinterval, 1)

数据量稳定性

每次请求或响应数据规模越接近，说明通信模板化程度越高。

CVsize = σsize / μsize
Ssize = 1 − min(CVsize, 1)

持续通信特征

长期持续存在的规律通信比短时突发连接更值得关注。

Sdur = min(Tactive / Tobs, 1)

Tactive 为活跃跨度，Tobs 为观察窗口。

分布平稳性

将观察窗口切分为多个时间片，若各窗口连接次数稳定，则提高可疑度。

CVfreq = σfreq / μfreq
Sdist = 1 − min(CVfreq, 1)

综合风险评分

四类特征归一化后进行加权融合，得到 0–100 的规则风险分。本系统将四类子分按等权重处理，使不同类型的 Beacon 行为特征都能参与最终判断。

Score = 100 × (0.25Stime + 0.25Ssize + 0.25Sdur + 0.25Sdist)

LSTM 模型

LSTM 模型用于补充规则引擎在复杂场景下的检测能力。相比固定规则，深度学习模型能够从多维连接特征中学习正常流量与 Beacon 流量之间更隐蔽的差异，尤其适用于存在随机抖动、低频心跳或弱周期特征的通信场景。

训练数据

模型训练数据来源于 ARES 2025 artifacts 中公开的网络流量数据。该数据目录同时包含 PCAP 与作者生成的 CSV 文件，其中以 benign 开头的文件标注为正常流量，以 cs 开头的文件与恶意流量相关，可标注为 Cobalt Strike / Malicious。

系统在此基础上完成协议解析、流级聚合、缺失值处理、异常值修正和标准化，从八十余项统计字段中筛选出 22 个与 Beacon 检测相关的连接行为特征。

数据集划分

采用分层随机抽样，保持正常样本与恶意样本在各子集中的比例一致。

训练设置

  • 损失函数：Binary Cross Entropy
  • 优化器：Adam，学习率动态调整
  • 正则化：Dropout + Early Stopping
  • 标准化：StandardScaler 统一特征尺度

自适应序列策略

系统会根据输入数据的记录形态自动组织模型输入：同一通信关系包含连续观测记录时，模型按时间顺序利用前后行为变化；记录较少时，则综合已有统计字段补足行为描述。

结果与发现

C2Sherlock 的核心发现是：隐蔽 C2 通信即使隐藏了内容，也很难完全隐藏行为。周期性连接、稳定数据量、长期持续访问和低流行度外部目标，往往会共同构成可疑信号。

发现一：行为比内容更稳定

即使 payload 被加密，连接时间、访问频率和通信持续性仍然能够反映 C2 行为特征。

发现二：多引擎互补更可靠

规则引擎适合快速筛查明显 Beacon，LSTM 模型适合捕捉复杂、弱规则的时序异常。

发现三：可解释报告降低研判成本

AI 研判将规则分数、模型概率和连接上下文转化为安全分析师可直接阅读的结论。

系统最终形成“检测 → 分析 → 研判 → 建议”的闭环，不仅告诉用户哪些连接可疑，也解释为什么可疑，以及后续应从哪些方向开展溯源。
