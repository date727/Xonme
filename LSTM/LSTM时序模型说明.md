# TCP Beacon LSTM 时序检测模型说明

## 1. 模型目标与定位

本模型用于识别 **TCP Beacon 型 C2 通信**：受控主机以相对稳定、但可能带有抖动的时间间隔，反复向同一 C2 服务端发起轻量 TCP 连接的行为。

其定位是 RITA 统计规则的辅助判决分支：

- RITA 擅长筛查周期明显、统计特征突出的可疑通信；
- LSTM 观察连续连接的间隔、抖动和连接形态，补充检测弱周期、随机抖动导致 RITA 分数不足的 TCP Beacon；
- LSTM 告警应与 RITA、Zeek 日志和后续溯源模块结合解释，不单独等同于最终归因结论。

当前模型覆盖 **全部 TCP 端口**，不把 IP 地址、端口号本身作为模型特征。因此它并不局限于 HTTP/HTTPS 的 80/443 端口。

> 边界：模型不覆盖 UDP、DNS 隧道、ICMP 隧道和持续长连接型 C2；这些通信仍主要由 RITA、Zeek 与后续协议专用模型处理。

## 2. 从 PCAP 到检测结果

```text
待检测 PCAP / PCAPNG
        ↓
解析 IPv4 / IPv6 中的 TCP 报文
        ↓
按 TCP SYN 重建连接；无 SYN 的残缺抓包保留并降低方向可信度
        ↓
按“源 IP、目的 IP、目的端口、TCP”形成通信组，并按时间排序
        ↓
每个 TCP 连接提取 24 维连接事件特征
        ↓
同一通信组连续 10 个连接构成一个时序窗口
        ↓
标准化后输入双层 LSTM，输出每个窗口的 C2 概率
        ↓
同一通信组取全部窗口中的最高概率作为组风险分数
        ↓
高于验证集确定的阈值时，输出 TCP Beacon 告警
```

连接在出现新的 SYN、或同一四元组 300 秒无报文时结束并重新开始计数。连续窗口绝不跨越 PCAP 文件或通信组边界。

## 3. 为什么建模相邻连接间隔

Beacon 型 C2 常见模式是“短连接—等待—短连接—等待”。同一次连接内部的包间隔会受到 TLS 握手、网络延迟和服务器响应影响；相比之下，同一主机到同一服务端的**相邻连接开始时间差**更直接反映回连周期。

即使 Beacon 设置了抖动，单个间隔可能不稳定，但连续多个间隔仍可能具有相近的中心周期、有限的离散程度和相似的轻量连接形态。LSTM 使用连续 10 个连接事件共同判断，而不是要求每次间隔完全相等。

## 4. 单个连接的 24 维特征

每个时间步对应一个重建出的 TCP 连接；每个时序窗口包含 10 个时间步，输入张量形状为 `(10, 24)`。

| 类别 | 字段 | 含义与作用 |
|---|---|---|
| 相邻连接间隔 | `flow_gap` | 本次连接与同组上次连接的开始时间差，是 Beacon 周期的基础信号。 |
| 长周期压缩 | `log_flow_gap` | `log(1 + flow_gap)`，降低 30 秒与数百秒周期的数值尺度差异。 |
| 局部周期 | `gap_rolling_mean`、`gap_rolling_median` | 最近 5 个连接间隔的典型水平，用于表达弱周期中心。 |
| 抖动程度 | `gap_rolling_std`、`gap_rolling_cv`、`gap_rolling_iqr` | 最近 5 个间隔的标准差、变异系数和四分位距，用于描述随机抖动而非只寻找严格周期。 |
| 连接规模 | `duration`、`orig_packets`、`resp_packets`、`orig_bytes`、`resp_bytes` | 表达连接持续时间、双向包数和字节量，区分轻量 C2 请求—响应与普通大流量业务。 |
| 双向比例 | `packet_ratio`、`byte_ratio` | 描述发起端与响应端的交互平衡情况。 |
| 连接内节奏 | `packet_iat_min`、`packet_iat_max`、`packet_iat_mean`、`packet_iat_stddev` | 当前连接内部相邻报文时间差的统计量。 |
| 前序包间隔 | `packet_iat_0` 至 `packet_iat_4` | 当前连接最早的 5 个包间隔，保留细粒度交互节奏。 |
| 方向可信度 | `direction_confidence` | 捕获到初始 SYN 时为高可信方向；缺失 SYN 的残缺抓包方向可信度较低，供模型区分数据质量。 |

特征在训练集中用 `StandardScaler` 拟合，并对训练、验证、测试和在线检测使用同一份 scaler。

## 5. 时序窗口与告警聚合

通信组键为：

```text
source_file + src_ip + dst_ip + dst_port + ip_protocol(tcp)
```

同组连接按 `start_time` 排序，以步长 1 滑动构造长度为 10 的窗口。一个含有 `n` 条连接的通信组最多能产生 `n - 10 + 1` 个窗口。

相邻窗口高度重叠。为避免超长抓包或单一通信组主导训练，训练、验证、测试均限制每组最多保留 200 个窗口；若超过上限，在整个时间范围内均匀抽取窗口，而非只保留开头。

在线检测中，模型先对每个窗口输出 C2 概率，再对同组窗口取最大值：

```text
group_score = max(window_score_1, window_score_2, ...)
```

`group_score` 超过阈值即判为可疑 Beacon。因而：

- **窗口级指标**：反映模型对每段连续 10 连接时序的细粒度识别稳定性；
- **连接组级指标**：反映系统能否发现一条独立 TCP 通信关系，是在线告警和与 RITA 协同时应优先使用的指标。

## 6. 模型结构与训练参数

模型为二分类双层 LSTM：

```text
Input (10 × 24)
  → LSTM(32, return_sequences=True, L2=1e-4)
  → Dropout(0.4)
  → LSTM(16, L2=1e-4)
  → Dropout(0.4)
  → Dense(32, ReLU, L2=1e-4)
  → Dense(1, Sigmoid)
```

- 损失函数：二元交叉熵；优化器：Adam，学习率 `0.001`；
- 批大小：16；最大训练轮数：30；
- 以验证集损失进行早停，耐心值为 4，并恢复最佳轮次权重；
- 使用类别平衡权重，缓解当前训练集中恶意窗口多于良性窗口的问题；
- 使用 5 个预设随机种子 `2026~2030` 独立训练，避免单次随机初始化决定结论；
- 最终部署模型仅依验证集选择，测试集不参与模型或阈值选择。

## 7. 数据划分与场景

数据文件放在 `LSTM/data/benign/` 和 `LSTM/data/malicious/`，划分由 `LSTM/data/split_manifest.csv` 固化。划分单位是 PCAP/场景，不是随机窗口，以避免同一抓包、相邻窗口或同一通信关系泄漏到训练和测试两侧。

当前重点场景如下：

| 集合 | 良性来源 | 恶意来源 |
|---|---|---|
| 训练集 | ARES Amazon/jQuery、IoT-23 Somfy | ARES Cobalt Strike run-1/run-2；TQH 30 秒/30% 抖动；TQH 300 秒/70% 抖动 |
| 验证集 | ARES Smashburger、IoT-23 Philip | ARES Cobalt Strike run-3 |
| 测试集 | IoT-23 Amazon | ARES Cobalt Strike run-4/run-5；TQH 30 秒/70% 抖动 |

TQH 的 30 秒/70% 抖动样本未用于训练或阈值选择，用来检验模型对未见抖动组合的泛化能力。

## 8. 阈值选择与当前结果

模型并非固定使用 `0.5` 阈值。对每个随机种子，在**验证集窗口**上枚举候选阈值，按以下规则选择：

1. 优先满足 C2 召回率 `≥ 98%` 且良性误报率 `≤ 5%`；
2. 在满足约束的阈值中，优先更高的召回率、更低的误报率、更高 F1；
3. 多个种子中，仍只根据验证集结果选择部署模型；当前选中随机种子 2029。

当前部署阈值为 `0.9998542070`。本轮测试的主要结果为：

| 口径 | C2 召回率 | 良性误报率 | F1 | 混淆矩阵 |
|---|---:|---:|---:|---|
| 窗口级 | 98.71%（998/1011） | 0%（0/131） | 99.35% | TN=131, FP=0, FN=13, TP=998 |
| 连接组级 | 100%（74/74） | 0%（0/9） | 100% | TN=9, FP=0, FN=0, TP=74 |

五次训练的窗口级召回率为 `98.28% ± 0.36%`，连接组级召回率为 `96.49% ± 2.63%`。

> 结果解释：连接组级结果最贴近在线告警，但当前测试仅有 9 个良性连接组；“0% 误报”应表述为“本次测试未观察到误报”，不能外推为真实环境误报率恒为 0。

## 9. 与旧 15 维模型的主要差异

旧模型使用 Zeek/ARES CSV 中的 15 个 `iat_oresp_*` 特征，主要反映单一流内响应端报文的间隔统计及前 10 个间隔，并且提取逻辑只覆盖目标端口 80/443。

当前模型的改进为：

1. **从 80/443 扩展到全 TCP 端口**，减少对 Web 端口的依赖；
2. **从单连接内部 IAT 扩展到相邻连接之间的间隔与抖动**，更贴近 Beacon 回连行为；
3. 新增滚动均值、中位数、变异系数、四分位距，显式描述弱周期和随机抖动；
4. 保留连接内包间隔信息，同时加入包数、字节数、双向比例和连接持续时间，减少仅凭周期产生误判的风险；
5. 从 PCAP 自动提取训练/在线一致的特征，避免训练 CSV 与在线处理逻辑不一致；
6. 使用 PCAP/场景级训练、验证、测试隔离，以及验证集专用阈值选择和多随机种子复验，降低随机窗口泄漏和“用测试集挑模型”的风险。

## 10. 当前限制与后续改进

1. 当前训练窗口中恶意样本多于良性样本。类别权重可缓解数量偏差，但不能代替更多样化的良性场景；应补充 HTTPS、云 API、软件更新、IoT 心跳、远程管理、数据库和消息队列等正常 TCP 通信。
2. 需要继续补充独立的良性 PCAP 与 C2 家族、端口、周期/抖动组合，以提高对真实环境泛化能力的可信度。
3. 若要覆盖 UDP、DNS 和 ICMP C2，应为各协议构建独立的事件重建、特征提取和时序模型，不能直接复用当前 TCP 模型。
4. 若数据集只有整份 PCAP 的恶意标签，需尽量依据数据集端点标注筛出真实 C2 通信组，避免将抓包中的背景连接全部当作恶意。

## 11. 相关文件与运行命令

- 原始 PCAP 与划分清单：`LSTM/data/`
- 特征提取脚本：`LSTM/src/prepare_pcap_dataset.py`
- PCAP 特征提取器：`backend/app/pcap_lstm_feature_extractor.py`
- 数据准备：`LSTM/src/data_prep.py`
- 训练脚本：`LSTM/src/train.py`
- 最终模型与 scaler：`LSTM/models/`
- 最终结果：`LSTM/logs/evaluation.json`
- 五次重复训练报告：`LSTM/logs/repeated_training_report.json`

常用命令：

```powershell
# 依据清单提取全部 PCAP 特征
python LSTM/src/prepare_pcap_dataset.py

# 训练五个随机种子并生成报告
python LSTM/src/train.py

# 若已分别完成各 seed，可仅执行最终验证集选模
python LSTM/src/train.py --finalize
```
